# Graphus v0.0.10

**Version:** 0.0.10
**Date:** 2026-07-21
**Tag:** `v0.0.10`

## Summary

Graphus v0.0.10 is a **feature and correctness release** for **Graphus**, the Label Property Graph
(LPG) database server written in Rust for extreme load and concurrency. It closes the last gaps to
**full Neo4j-5.x index and constraint parity**, extends the Cypher surface well beyond the openCypher
TCK core, and hardens the server for production with a family of **ACID-correctness and authorization
fixes** — several of them committed-data-loss or authentication/authorization defects that a green
test suite did not catch, found by a dedicated multi-specialist adversarial audit and each pinned by a
non-vacuous regression test.

Throughout, the four inviolable guarantees held:

- **100% ACID** — full transactional reliability under power loss, faults, and crashes.
- **100% openCypher TCK** — **3914 / 3914** scenarios passing.
- **100% Bolt protocol** — byte-for-byte interoperability with the Neo4j driver ecosystem.
- **100% PackStream** — exact wire-level serialization.

## Highlights

- **Full Neo4j-5.x index parity, for nodes *and* relationships.** Every Neo4j index kind is now
  served: TEXT (trigram) for `CONTAINS`/`ENDS WITH`/`STARTS WITH`, FULLTEXT (with
  `db.index.fulltext.query*`), POINT (spatial), composite (multi-property) RANGE,
  relationship-property indexes including a relationship RANGE index, existence (`IS NOT NULL`) index
  scans with `ORDER BY` served by the index, and VECTOR (HNSW) indexes with the
  `db.index.vector.query*` procedures and `vector.similarity.*` functions — plus a unified,
  Neo4j-conformant `SHOW INDEXES` and named node-property indexes with a durable, globally-unique name
  catalogue.
- **Full Neo4j-5.x constraint parity.** Composite property-uniqueness, node-key and relationship-key
  constraints, and relationship existence/type constraints, all enforced at the write path.
- **A large tranche of the Cypher surface beyond the TCK core** — quantified path patterns, `CALL {}`
  subqueries, `COUNT {}` expressions, additional functions, and more.
- **A production-hardening ACID & security pass.** A multi-specialist adversarial audit found and
  fixed defects a green suite missed — including a **critical Bolt pre-authentication bypass**, a
  **critical off-thread-reader snapshot-isolation property loss**, a family of `DENY READ`
  authorization leaks on indexed reads, and two authentication denial-of-service / brute-force gaps.
  See **Security** and **Fixed** below.
- **The examples suite is now a falsifiable gate**, measuring real index seeks by `dbHits` and WAL
  volume by bytes actually written, so an example proves a claim rather than asserting a plan string.

## Added

- **Full Neo4j-5.x index parity (rmp #646, #655-#671, #676-#680, #623-#627).** Every Neo4j index kind
  for nodes and relationships: TEXT (trigram) with a bounded `STARTS WITH` prefix seek; FULLTEXT
  (node, multi-label, and relationship, with a working `db.index.fulltext.queryRelationships`); POINT
  (spatial) with a real spatial seek; composite (multi-property) RANGE with multi-key seek;
  relationship-property indexes end-to-end and a relationship RANGE index serving `<`/`<=`/`>`/`>=`;
  existence (`IS NOT NULL`) index scan with `ORDER BY` served by the index (Sort elision); and VECTOR
  (HNSW) — the ANN structure, a durable catalog and coordinator wiring, `CREATE`/`DROP VECTOR INDEX`
  DDL with `OPTIONS`/`indexConfig` and `SHOW … type=VECTOR`, and the `db.index.vector.query*`
  procedures plus `vector.similarity.*` functions. A unified, Neo4j-conformant `SHOW INDEXES` across
  every kind (full column set, filters, `YIELD`/`WHERE`), DDL `OPTIONS` and `IF (NOT) EXISTS`
  completeness with a unified `DROP`, and **named node-property indexes** with an optional name,
  `DROP INDEX <name>`, and a durable named-index catalogue enforcing global name uniqueness.
- **Full Neo4j-5.x constraint parity (rmp #650-#654).** Composite property-uniqueness, node-key,
  relationship-key, and relationship existence/type constraints, enforced at the write path.
- **Cypher surface beyond the openCypher TCK core (rmp #630-#649 and related).** Quantified path
  patterns, `CALL {}` subqueries, `COUNT {}` expressions, and additional functions.

## Fixed

Correctness fixes across the index-build / MVCC / WAL-recovery paths. Several are committed-data-loss
or silent-degradation bugs a green test suite did not catch; they are called out so an operator can
judge their own exposure.

- **GC no longer severs an in-flight off-thread reader (rmp #821, ACID-Isolation — CRITICAL).**
  `gc_property_chain` zeroed a reclaimed tombstone's forward pointer on a **live** owner's chain, so a
  concurrent auto-commit reader walking the chain silently dropped every committed, snapshot-visible
  property below the tombstone. A threaded stress reproduced ~7.4% lost reads on the unfixed code. The
  reclaim now **preserves** the forward pointer so a reader threads through to the live successor,
  mirroring the relationship-chain fix.
- **A clean, fully-committed WAL now always recovers (rmp #806, ACID-Durability — CRITICAL).** A clean
  log refused to recover when its first retained record's length was a multiple of 256 (a leading zero
  byte was misread as padding), which could mis-report interior corruption and reset the transaction
  id high-water. Recovery now disambiguates a leading-zero run with a CRC-checked decode probe.
- **A VECTOR (HNSW) build no longer bakes an uncommitted embedding (rmp #780), and a poisoned
  full-text/spatial marker no longer degrades every such index database-wide permanently (rmp #803).**
- **A relationship dead-link corpse no longer severs an in-flight off-thread reader mid-walk during GC
  (rmp #811).**
- **FULLTEXT/VECTOR procedures honour index state and fail closed on a read fault (rmp #733).**
- Numerous smaller correctness fixes (a QPP/variable-length query can no longer abort the server;
  `stdev`/`stdevp` aggregates; `REMOVE n.p` constraint enforcement; `DENY`-across-labels precedence;
  `SHOW INDEXES` build progress; and more — see the changelog).
- **The MVP UDS crash-recovery E2E tests are deterministic under a full-workspace run (rmp #819)** — a
  test-harness robustness fix (not a server defect) that makes the release gate honest and repeatable.

## Security

- **Closed a Bolt pre-authentication RESET authentication bypass (rmp #820, CWE-306 — CRITICAL).** A
  failure *before* authentication (a malformed/absent `HELLO`, a failed `LOGON`, or an out-of-order
  message) entered the RESET-recoverable `FAILED` state instead of the spec-mandated terminal
  `DEFUNCT`, so an unauthenticated client could send junk → `RESET` → `RESET` → `RUN` and reach
  `READY` with a `None` principal — treated as **unrestricted** — running arbitrary read+write queries
  over Bolt (TCP and UDS) with no credentials. Every pre-auth failure is now terminal, with a
  defense-in-depth guard in `RESET`; the correct post-auth recovery is preserved.
- **Node index-seek / precise-scan and the named full-text/vector index procedures now honour
  `DENY READ` property masking for a restricted principal (rmp #822 / #826, CWE-863).** The fused node
  read paths and `db.index.fulltext.query*` filtered candidates only on node visibility, so
  `WHERE n.p = v` (or a full-text match) on a `DENY READ` property leaked *which* nodes carry a value
  while `RETURN n.p` shows `null`. They now gate on read access to every covered property, matching the
  `node_property` masking exactly.
- **Bolt `LOGON` is now subject to the per-account brute-force lockout (rmp #823, CWE-307)**, sharing
  one throttle with REST; and **a global bound on concurrent password verifications stops a
  username-rotation Argon2 amplification DoS (rmp #824, CWE-770)**, shedding before the KDF,
  username-independently.
- **Closed a username-enumeration timing oracle in password authentication (rmp #812, CWE-208 /
  CWE-203).** Unknown-user and suspended-user branches now perform an equal-cost Argon2id verification;
  the measured differential collapsed from ~9193× to within noise.

## Verification

This release was validated empirically; no functional test reported an error. The four inviolable
guarantees are unchanged — the openCypher TCK remains at **3914 / 3914** (100%), and the ACID, Bolt,
and PackStream guarantees hold.

- **Consolidated release gate (green):** `cargo fmt --all --check` clean; `cargo clippy --workspace
  --all-targets -- -D warnings` clean; `cargo test --workspace` = **5362 passed, 0 failed**; and the
  openCypher TCK conformance suite (`graphus-tck`) = **3914 / 3914**.
- **Every audit finding is pinned by a non-vacuous RED→GREEN regression test** — proven to fail on the
  unfixed code and pass after the fix, including the pre-auth bypass (the exploit's query reaches the
  executor on the unfixed code), the off-thread-reader property loss (~7.4% lost reads reproduced by a
  threaded stress), and the `DENY READ` index-seek leaks.

## Compatibility

v0.0.10 is a **drop-in upgrade** from [v0.0.9](v0.0.9-20260708.md). The transaction and isolation
model is unchanged (MySQL-style autocommit reads at Snapshot Isolation, fully Serializable writes and
explicit `BEGIN … COMMIT`; see [`docs/transactions.md`](../docs/transactions.md)). No existing public
Cypher, Bolt, or REST contract was removed or changed incompatibly; the additions are index/constraint
kinds and Cypher features that were previously unsupported.

Operators running with RBAC `DENY READ` privileges, or exposing Bolt to untrusted clients, should
upgrade: the authorization and pre-authentication fixes above change previously-incorrect behaviour to
the correct, Neo4j-conformant one. **No configuration change is required** to upgrade.
